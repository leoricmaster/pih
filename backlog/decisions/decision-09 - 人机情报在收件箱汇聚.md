## Context

TASK-1.03.01 要求人工情报（文本/文件/录音）30 秒内录入，且**走与自动采集完全相同的处理链与质量闭环**（AC2/AC3：同一结构化链路、同一聚类与核实、无差异对待）。人工情报在架构上从哪里进入流水线？

**方案 A：人工直通入库**（录入即结构化字段，跳过处理链）
- 优点：录入即得结构化，看似快
- 缺点：双轨制——质量门、Admiralty 评级、聚类核实全部绕过，质量闭环对人工情报失效，直接违反 AC3

**方案 B：录入触发专属 LLM 链**（独立的人工情报处理代码）
- 优点：可为人工场景定制提示词
- 缺点：两套处理代码必然漂移；"同一流水线"承诺名存实亡

**方案 C：录入网关只做「落盘 + 入 inbox」**，之后完全复用主处理链
- 优点：单链路、单套质量门；人工与机器情报在收件箱（inbox）汇成一链
- 缺点：人工素材形态（照片/录音）需适配器侧渐进支持（转写等子能力已是独立故事，TASK-1.03.01 验收面注明渐进明细）

## Decision

采用方案 C。处理链的唯一输入抽象为 **inbox 条目**（raw 文本 + 附件引用 + 来源标记）；信源适配器与录入网关都只是 inbox 的生产者（架构 §6.5）。

配套规则：
- 人工来源 `source_type=manual`，Admiralty 来源可靠性默认 A/B（本人一手见闻），信息可信度照常由抽取与核实评定——"仍需事实核查"（AC2）；
- **录入即时可见**：网关落盘即返回，条目以 `pending` 态进 Web 列表，结构化异步完成——"≤30 秒"约束的是人的操作时间，不等待 LLM。

**理由**：AC 已把"同链"定为验收条件；C 是唯一同链且不双轨的方案。可靠性语义（先落盘可重放，ADR-007）对人工情报同样成立——录入内容也是原始素材，同样值得可重放保护。

## Consequences

- 处理链对来源零特判，质量门与降级语义天然覆盖人工情报；
- Agent 贡献者线索回写（draft-001）复用同一网关接口，仅换认证方式；
- 录音转写、纪要结构化等增强在网关侧叠加（预处理），不动主链；
- inbox 条目需带来源类型与默认可靠性字段（架构 §7）。
