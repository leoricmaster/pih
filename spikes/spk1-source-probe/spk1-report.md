## 3. 工程化要点与局限

### 3.1 进正式采集器的实证要点

1. **状态码不可信**：cncma 软 200（一切路径 200 HTML）、d1cm 软 404（404 标题配 200）——判存在性必须看 `<title>`/正文结构；
2. **编码兜底**：响应头无 charset 时 GBK 页按 ISO-8859-1 乱码（cehome 实证）——头 charset → meta charset → utf-8/gbk 严格试探的解码链必须有；
3. **CCMA HTTP-only**（https 超时），采集器需容错；
4. **KHL Crawl-Delay 10**：单源吞吐上限 ~6 页/分钟，调度须按源配置间隔；
5. **徐工须走 AJAX 端点**（`/ext/ajax_news.jsp?flag=getdata&channelId=22519` + year/month 参数，等价浏览器行为），且不带 year/month 时 pageNo 翻页不前进（异常，原因未确认）。

### 3.2 Spike 脚本已知局限（Task 3 审查确认，正式采集器须解决）

1. **交错间隔未计**：robots.txt 检查请求与详情请求交错时，robots 请求可能紧跟上一详情请求发出，未计入 ≥2s 节流口径；
2. **白名单死代码**：`extract_links` 详情 URL 白名单含 3 个未经任何实抓验证的形态——`-detail-`（徐工）、`bid-`（千里马）、`art_`（CNIPA），对应源均未实抓，规则正确性未知；
3. **详情上限仅单次运行累计**：`DETAIL_LIMIT - saved` 只在单次进程内累计，跨运行重跑即重置，不构成全局配额；
4. **meta charset 只扫前 2048 字节**：声明位置靠后即漏检，回退 utf-8/gbk 严格试探（多数情况可救，非保证）。

### 3.3 未验证项（如实记录，接入时验证）

- cehome 深分页（共 12,127 页）：实抓仅取第 1 页；摸底观察 page30/200 疑似截断/缓存，未验证；
- 三一列表最深页数未确认（第 1 页可见 page 0–5）；
- 徐工 AJAX 翻页异常（不带 year/month 返回相同 id 集）未验证；
- KHL 近期内容发现能力弱：最新 sitemap 分片仅 2–3 条 URL，集团站 /news 为品牌导航页，行业新闻在登录墙子品牌——**这是 KHL 降为观察级的核心依据**；
- 千里马频控阈值仅有摸底观察（连抓 2–3 详情触发 419，静置 30–60s 恢复），未实抓复验；区域门户无可用翻页（index_2 软跳 404）；
- lmjx、CNIPA 未实抓（摸底已判定：WAF 全站拦截 / 检索本体反爬）。
