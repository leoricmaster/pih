# 产品情报中心（Product Intelligence Hub）需求文档

- 版本：V0.9（Backlog 重构同步）
- 日期：2026-08-25
- 状态：待评审
- 定位：面向产品规划与产品设计的行业/竞品情报收集、核实、结构化沉淀与检索系统
- 变更：V0.8→V0.9 配合 Backlog V0.8 纯需求树重构——§4 序言改为需求树引用，§8 收纳原 Backlog 承载的初期验收门槛；附件 A 信源清单经 SPK-1 实测锁定（9 源，铁甲网域名修正为 cehome.com）；§7 LLM 抽取错误风险行补 SPK-2 实测结论

## 1. 背景与目标

### 1.1 背景

产品规划依赖两类信息：一手信息（实测、访谈）与二手信息（互联网公开信息、行业交流）。当前痛点：

- 互联网情报分散在数十个信源，靠人工盯，覆盖不全、易遗漏；
- 情报可信度参差不齐，缺乏统一的核实与标注机制，规划决策时不敢直接用；
- 情报散落在聊天记录、个人笔记、会议纪要中，无法沉淀复用，人员流动即流失；
- 竞品参数、功能对比靠临时整理，重复劳动。

### 1.2 目标

建设一个**行业无关、可持续运行**的情报系统：

1. 由智能体自动完成互联网情报的采集、核实、结构化入库；
2. 兼容人工情报来源（参会见闻、行业交流、内外部访谈、会议纪要等）的统一录入与处理；
3. 产出为可检索的情报库 + 结构化竞品档案，直接服务于产品规划与产品设计；
4. 通过"领域包"配置化机制，支持快速切换到其他产品线/行业。

### 1.3 非目标

- 不做一手实测数据管理（试验数据、测试报告属于 PLM/数据平台范畴）；
- 不做舆情情感分析、电商评论分析（属于用户研究/营销范畴）；
- 不追求"全自动决策"——系统产出情报与判断依据，决策权在人；
- 不做信源管理 UI、领域包插件机制与导入导出 UI——配置文件即管理界面（信源 ≤10、领域包 1 个的规模下最优，多领域真实需求出现后再议）；
- 不做权限体系——单用户内网部署阶段，静态凭据足够。

## 2. 可行性

- **资源约束**：1 人承担开发与运营。由此推出——自部署组件最少化（每个常驻服务都有升级/备份/排障成本，引入须论证）；无人值守流水线须高度自动化，人工环节集中在"终态确认"与"周报精选"；代码优先而非低代码平台（可测试、可版本化、可 review 的代码资产比可视化画布更可维护）。
- **技术可行**：网页采集、RSS、变更监控、LLM 结构化抽取、混合检索均为成熟技术，无空白点；语义理解贯穿全链路，LLM 能力与端点均可配置分级。主要技术风险在反爬与抽取准确率，有成熟缓解手段（见 §7）。
- **业务可行**：威胁情报领域（CTI）已有数十年验证的方法论可迁移——来源分级、Admiralty Code 置信度标注、多源交叉印证。核心风险是运营性的而非技术性的：情报"采而不用"（见 §7），故系统设计以"被检索使用"为第一指标。
- **通用性**：核心域模型（主体—事件—来源—置信度—时效）行业无关；行业知识（信源、关键词、竞品、标签树、模板、提示词）封装为"领域包"配置，切换/新增领域 = 改配置，不改核心代码。

## 3. 用户与使用场景

### 3.1 角色模型

| 角色 | 职责 | 接口 | 承担者示例 |
|---|---|---|---|
| 运营者 | 维护信源与领域包、处理待核实队列、纠正误判 | 配置文件、核实操作（CLI/API） | 情报运营人员、管理 Agent |
| 消费者 | 主动检索与问答；被动接收简报与推送 | 只读 Web、查询 API、推送渠道 | 产品规划/设计人员、管理层、规划 Agent |
| 贡献者 | 录入参会见闻、访谈纪要等非互联网情报 | 录入网关（与自动采集同一流水线） | 业务人员、外部采集 Agent |

### 3.2 核心场景

1. **日常监控**：系统自动盯信源，重要情报（新品发布、中标、专利）当日推送；
2. **按需检索**：规划/设计/专题分析任何需要时——"竞品 X 的遥控功能迭代历史？"——结构化筛选、详情溯源，直至自然语言问答；消费方为人（Web）与 Agent（只读 API，见 §4.5）；
3. **专题调研**：发起"3D 引导系统竞品对比"任务，智能体限时深挖并产出报告；
4. **情报录入**：参展回来，丢入照片/录音/笔记，系统自动结构化入库；
5. **定期简报**：周报（动态）+ 月报（趋势与格局变化）。

## 4. 功能需求

> 按能力组织；条目化需求与验收标准见 Backlog（需求树；实现顺序由 Sprint 规划决定），实现细节（框架、数据结构、状态机、排序函数）见架构文档。

### 4.1 信源管理

- 信源以配置文件注册与变更（URL、类型、采集方式、更新频率、来源层级），变更留痕；
- 来源层级定义：
  - L1 官方一手：主机厂官网/财报、专利局、标委会、招投标公示；
  - L2 行业权威：CCMA 协会、KHL、Off-Highway Research、铁甲网；
  - L3 泛媒体：行业自媒体、新闻报道；
  - L4 弱信号：社交内容、招聘信息（仅作线索，须印证后升级）；
- 信源健康监控：抓取失败告警（推送至个人渠道）、信源失效检测；
- 信源画像：来源可靠性评级证据驱动——基于核实日志的历史结局（被证伪率、首发率）重估。

### 4.2 采集流水线

- 定时调度抓取（按信源频率）；
- 去重（URL 指纹 + 内容相似度）；
- 相关性粗筛：领域包关键词 + LLM 二分类（小模型），过滤无关内容；
- 原文存档：快照入对象存储，供回溯与引用；无快照不入库。

### 4.3 核实引擎

- **来源分级**：自动读取信源层级；
- **置信度标注**：Admiralty Code 二维评级——来源可靠性 A–F × 信息可信度 1–6（如 B2），LLM 预评级与人工评级共用同一词表；
- **核实状态机**：状态挂事件层；中间态（待核实→单源确认）自动流转，终态（多源确认/已证伪）必须人工确认、全程留痕（完整语义见架构 §6.1）；
- **交叉印证**：同事件多信源自动聚类；双独立信源时事件标记"已具备升级条件"，进入人工队列；
- **事实/推断分离**：抽取时强制区分客观事实与主观推断，推断必须携带依据；
- **时效管理**：每条情报带采集时间与有效期（定价/参数类默认 6 个月），过期自动降权并提示复核；
- **人工核实队列**：低置信度、冲突、"已具备升级条件"的情报进入人工队列，运营者一键确认/证伪。

### 4.4 情报库

每条情报记录字段：

```
情报ID | 采集时间 | 有效期
主体（公司 + 产品线，如"三一 SY375 遥控版"）
事件类型（新品发布/功能迭代/专利公开/中标落地/组织人事/价格变动/标准动态/行业统计/行业合作/财报/其他）
事实描述（含量化参数：遥控距离、定位精度、效率提升% 等）
推断与判断（独立字段，含依据）
来源（URL + 快照 + 来源层级）
置信度（Admiralty Code，如 B2）
所属事件ID
关联标签（领域包标签树，如 #无人化 #远程遥控 #3D引导 #矿山场景）
```

另维护两类结构化资产，随情报入库更新、人工可修正：

- **竞品档案**：每个竞品主体一页，聚合其全部情报与基本信息；
- **功能/参数矩阵**：竞品 × 功能项（有/无/规划中/版本）、关键性能参数表。

### 4.5 检索与问答

- **结构化筛选**：按 主体/事件类型/时间/标签/置信度 组合过滤；检索结果默认按"置信度 × 时效"排序（排序函数见架构 §6.2），过期与低置信内容显式标注；
- **情报详情**：schema 全字段（事实/推断分区）+ 所属事件状态与核实流转历史 + 原文快照与原始链接双入口；
- **只读查询 API**：结构化筛选与详情同时以 JSON API 暴露，供 Agent 消费者按相同条件组合查询，响应含 情报 ID、来源引用、置信度、事件核实状态，排序与 Web 一致（部署与鉴权见架构 ADR-006）；
- **自然语言问答**：答案必须携带引用（情报 ID、来源、置信度）；混合检索覆盖竞品型号等精确 token 查询；问答接口对人与 Agent 同一（`ask()`）。

### 4.6 报告与推送

- 周报：本周重要情报（按事件类型分组）+ 待核实清单；
- 月报：趋势归纳、竞品动态对比、值得关注的弱信号；
- 即时推送：一级信源的重大事件（新品/中标/高管变动）当日推送；
- 推送渠道：企业微信/邮件可配置。

### 4.7 情报录入

- 统一录入入口：文本/文件/语音，走与自动采集同一流水线（来源类型=人工，来源可靠性默认 A/B 级，仍需事实核查）；
- 体验红线：单次录入 ≤30 秒；
- Agent 贡献者的线索回写复用同一入口；
- 录入激励与流转机制，鼓励非互联网情报沉淀。

### 4.8 专题调研

- 发起调研任务（如"3D 引导系统竞品对比"），智能体限时深挖并产出报告。

### 4.9 领域包管理

- 领域包 = {信源清单, 监控关键词, 竞品主体清单, 标签树, 报告模板, 抽取提示词}；
- 以配置文件维护，带 schema 校验（缺必填字段拒绝加载），支持启停与版本化（变更留痕），支持多领域包并存与切换；
- 首个内置领域包：工程机械·挖机智能化（附件 A）。

## 5. 非功能需求

- **可维护性**：信源适配器插件化（新增信源不改核心代码）；领域包配置化，切换行业零代码改动；
- **可观测性**：采集成功率、粗筛通过率、核实积压量、检索使用次数均有指标，单机看板或 CLI 报表呈现；
- **可靠性**：流水线各阶段失败不丢数据（原始内容先落盘再处理，处理失败可重试/重放），LLM 调用带重试与降级（详见架构 §8）；
- **数据合规**：遵守 robots 协议与版权边界，库存快照与引用链接而非全文转载（对外分享时）；法务评审前置（见 §6）；
- **部署**：单机可部署，自部署组件最少化（引入须论证运维成本）；数据可导出，避免供应商锁定；
- **成本**：LLM 分级调用（粗筛用小模型，核实/抽取按需用大模型），端点可配置（支持自有模型服务）；月度成本可监控（目标与公式见架构 §9.2）。

## 6. 法务与合规

| 事项 | 边界 | 处理 |
|---|---|---|
| robots 协议 | 尊重目标站点 robots | 采集器默认遵守，个别信源白名单需记录理由 |
| 版权内容 | 快照仅内部留存，不对外转发 | 对外仅给链接+摘要 |
| 招投标、招聘数据 | 商业用途存在真实法律边界（反不正当竞争法下有判例） | 开发前法务确认，结论回写本章 |
| 专利数据 | 国知局批量抓取受限 | 优先官方开放接口/授权渠道，批量抓取需法务确认 |
| 个人信息 | 招聘信息含个人信息；人事动态涉及个人信息 | 最小化存储（不存简历级个人数据），PII 字段脱敏可配 |

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 采而不用，系统沦为信息坟场 | 高 | 以"检索使用次数"为北极星指标（§8）；周报强制人工精选而非全量推送；以开发者本人真实使用验收 |
| 1 人项目不可持续（个人精力中断即停摆） | 高 | 全部资产代码化/配置化（可迁移）；文档即运营手册 |
| 待核实队列积压 | 中 | 待核实超期自动降级归档；运营预算内优先清队列 |
| LLM 抽取错误污染情报库 | 中 | 重要字段低置信强制人工复核；快照可回溯；人工核实队列纠正错抽。SPK-2 实测（2026-08-25，MiniMax-M3 25 样本 3 轮）：枚举命中率 52–56%，但字段级严格相等准确率仅 25–31%，瓶颈在自由文本字段（事实描述/推断）措辞改写即判错——生产评分应改语义相似度或子串包含，提示词需 few-shot 锚定金答案风格 |
| 信源反爬/失效 | 中 | SPK-1 实测（2026-08-25，8 类摸底 + 5 源实抓 25 样本）：实抓 5/5 可抓、零反爬触发；已知拦截集中于 3 类——路面机械网（百度 WAF，真人复核通过前不采集）、CNIPA 专利检索本体（瑞数反爬，改道官方数据产品）、千里马（频控，≥60s 间隔可控，法务确认前不启用）。维持信源健康监控 + 适配器插件化，坏一个换一个 |
| 版权/数据合规 | 中 | §6 边界表；法务前置确认 |
| 通用性过度设计拖慢交付 | 中 | 领域包=配置文件（非插件机制）；通用性验收推迟到第二领域真实接入 |
| 单机数据丢失 | 中 | 数据库每日备份 + 快照版本化，备份脚本进 repo |

## 8. 成功指标

- **北极星指标**：情报库的周均检索使用次数（Web 访问 + API 调用合计，初期以核心用户计）；
- **辅助指标**：待核实积压量、周报打开率、情报被引用进规划文档的次数、人工核实中纠正的错抽条数。

**初期验收门槛**（随开发渐进明细与校准）：

- 真实检索 ≥ 20 次且三档记录；
- 无人值守运行 4 周，中断 ≤ 1 次；
- 入库情报 ≥ 60 条（参考值）；
- 快照回溯抽样 20 条全部可溯；
- 查询 API 与 Web 同源可用（外部 AI 可接入）。

## 附件 A：首个领域包——工程机械·挖机智能化（初始配置）

**竞品主体（初始）**：三一重工、徐工机械、中联重科、柳工、山东临工、卡特彼勒、小松、日立建机、沃尔沃建筑设备、现代/迪万伦；方案商：拓疆者、网易伏羲、伯镭科技、Teleo、Built Robotics；机控系统：Trimble、Topcon、Leica。

**初始信源（≤10，SPK-1 实测锁定，详见 `spikes/spk1-source-probe/spk1-report.md`）**：

1. CCMA 协会（cncma.org，列表页 HTML 解析，HTTP-only）
2. 三一集团新闻页（sanygroup.com，列表页 HTML 解析，SSR）
3. 徐工集团新闻页（xcmg.com，公开 AJAX 端点解析）
4. 铁甲网（cehome.com，列表页 HTML 解析；原线索域 toujian.com 为弃置域，实测修正）
5. 第一工程机械网（news.d1cm.com，列表页 HTML 解析）
6. KHL（khl.com，News Sitemap 解析——观察级非主选：可抓但近期内容发现能力弱，不作日常采集）
7. 千里马招标网（qianlima.com，低频列表轮询 + 详情直抓，无人化/遥控关键词——法务确认前不启用）
8. 国家知识产权局专利公布（检索本体反爬不可爬，改道官方数据产品/授权渠道，非爬取）
9. 中国路面机械网（lmjx.net，WAF 拦截待真人复核——复核通过前不采集）

**初始标签树**：无人化作业 / 远程遥控 / 3D 引导与机控 / 电动化 / 智能辅助施工 / 场景（矿山·港口·市政）/ 核心零部件（电液控制·传感器）。

**初始监控关键词**：无人挖掘机、遥控挖掘机、自主作业、3D 引导、坡度控制、电子围栏、一键刷坡、称重系统、远程操控座舱。
